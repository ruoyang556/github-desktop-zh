# GitHub Desktop 汉化教程（通用版）

> 已在本机 **GitHub Desktop 3.6.7 (Windows)** 实测：全新安装 → 运行一键脚本 → 中文界面。
> 项目说明与设计细节见 [../README.md](../README.md)，贡献方式见 [../CONTRIBUTING.md](../CONTRIBUTING.md)。
> 文中命令均在**仓库根目录**执行。

## 零、脚本能力一览（v1.0）

```powershell
pwsh -File .\一键汉化.ps1            # 汉化最高版本（自动定位、自动备份、全量重建）
pwsh -File .\一键汉化.ps1 -All       # 汉化所有已安装版本
pwsh -File .\一键汉化.ps1 -DryRun    # 预演：只报命中，不写文件
pwsh -File .\一键汉化.ps1 -Scan      # 扫描没覆盖的英文 -> scan-app-x.y.z.txt
pwsh -File .\一键汉化.ps1 -Restore   # 还原英文原版
pwsh -File .\一键汉化.ps1 -AppDir "<path>"   # 指定 resources\app
```

执行流程：备份 → 以**备份的原始文件**为源做全量重建（幂等、不残留旧补丁）→ 整串替换 → 模板正则替换 → 追加原生菜单钩子 → 部署 zh-cn.js → 注入 index.html。

## 一、先回答版本问题

| 问题 | 答案 |
|---|---|
| 有没有版本限制？ | **没有硬编码版本号**。脚本自动扫描 `%LOCALAPPDATA%\GitHubDesktop\app-*`，取版本号最大的目录。3.x 全系通用。 |
| 换了版本还能用吗？ | 能。词典是按「英文原文」匹配的，跨小版本命中率很高（3.6.x 实测 662 条 / 665 处）。官方更新会新建 `app-新版本` 目录，重跑一次脚本即可。 |
| 会不会因为版本不同报错？ | 不会。命中不了的词条自动跳过，剩余文案由运行时兜底层（zh-cn.js）继续处理。 |
| 有什么前提？ | 安装目录必须是「解包形态」，即存在 `resources\app\renderer.js`。3.x 官方安装包都是这种结构。若哪天改成 `app.asar`，先用 `npx asar extract app.asar app` 解包，再跑脚本。 |

## 二、一键脚本（推荐，30 秒）

### 1. 准备
把整个 `H:\KaiFa\ghd-zh` 目录拷到任意位置（比如 `D:\GHD-中文`），确保里面有：

```
一键汉化.ps1          <- 主脚本
dict1.tsv ~ dict6.tsv <- 界面文案词典（英文<TAB>中文）
main-dict.tsv         <- 菜单词典
out\zh-cn.js          <- 运行时兜底层
backup\               <- 会自动生成原始文件备份
```

### 2. 运行

```powershell
# 正常安装（会自动关闭正在运行的 GitHub Desktop）
pwsh -File .\一键汉化.ps1

# 只看会命中多少条，不写文件
pwsh -File .\一键汉化.ps1 -DryRun

# 指定某个版本目录
pwsh -File .\一键汉化.ps1 -AppDir "C:\Users\你\AppData\Local\GitHubDesktop\app-3.6.7\resources\app"

# 还原英文原版
pwsh -File .\一键汉化.ps1 -Restore
```

> 没有 pwsh 也行：右键 `一键汉化.ps1` →「使用 PowerShell 运行」。
> 脚本带 UTF-8 BOM，Windows PowerShell 5.1 不会乱码。

### 3. 完成
重新打开 GitHub Desktop，界面即为中文。典型输出：

```

  目标目录: ...\app-3.6.7\resources\app
  原始文件备份: ...\backup\app-3.6.7
  界面词条: 689   菜单词条: 103
  renderer.js: 命中 662 条词条 / 665 处替换
  main.js    : 命中 103 条词条 / 103 处替换
  已写入 renderer.js / main.js
  已部署 zh-cn.js（运行时兜底）
  已在 index.html 注入 zh-cn.js
完成！启动 GitHub Desktop 即为中文界面。
```

## 三、脚本到底改了什么（原理）

GitHub Desktop 是 Electron 应用，界面文案全部硬编码在资源里，没有语言包。所以分三层：

| 层 | 目标文件 | 做法 | 效果 |
|---|---|---|---|
| ① 打包层 | `resources\app\renderer.js` | 对 689 条「完整英文字面量」做精确替换（只替换被引号完整包裹的多词短语，绝不碰逻辑标识符） | 主界面、对话框、提示语变中文，零运行时开销 |
| ② 主进程层 | `resources\app\main.js` | 替换菜单 `label:` 与对话框 `title:` 字面量（含 `&F` 助记符） | 文件/编辑/视图/仓库/分支/帮助 菜单变中文 |
| ③ 运行时层 | `resources\app\zh-cn.js`（新增）+ index.html 一行注入 | DOM 观察器：单词标签（Changes→改动）、动态拼接（Commit 1 file to main→提交 1 个文件到 main）、相对时间（12 minutes ago→12 分钟前） | 兜住前两层覆盖不到的动态文本 |

**安全性设计**：
- 打包层词典里 **没有一个是裸单词**（全部是带空格的短语），所以不会误伤 `e[e.Commit=0]="Commit"` 这类枚举/逻辑常量。
- 单单词只在 DOM 显示层替换，不触碰数据。
- `<pre>/<code>/<textarea>/输入框` 内的内容跳过，不会把你的代码、diff 内容改成中文。
- 全程只改 4 个文件，随时可 `-Restore` 还原。

## 四、手动做（不想跑脚本）

### 方案 A：最省事（只有运行时层，零风险，覆盖率约 60%）

1. 完全退出 GitHub Desktop（托盘也要退）。
2. 打开 `%LOCALAPPDATA%\GitHubDesktop\app-<版本>\resources\app`。
3. 把 `out\zh-cn.js` 复制进去。
4. 用记事本打开同目录的 `index.html`，在 `</head>` 前插入一行：
   ```html
   <script defer="defer" src="zh-cn.js"></script>
   ```
5. 保存，启动。界面会出现中文（菜单仍是英文）。

### 方案 B：完整汉化（含菜单和文案）

1. 先备份 `renderer.js`、`main.js`、`index.html`。
2. 用任意文本编辑器（VS Code / Notepad++，**必须保持 UTF-8 无 BOM**）打开 `renderer.js`，
   按 `dict1~8.tsv` 里的 `英文<TAB>中文` 逐条「查找替换」（**先替换长句，再替换短句**，否则短句会把长句拆坏）。
3. `main.js` 按 `main-dict.tsv` 同样处理。
4. 再做方案 A 的第 3、4 步。
5. 启动。

> 手工替换容易漏、容易顺序错，所以建议直接用脚本。

## 五、自己扩充词表

1. 发现界面还有英文，例如 `Bypass Commit hooks`：
   - 打包层的：在 `dict6.tsv` 追加一行（Tab 分隔，不要用空格）：
     ```
     Bypass Commit hooks<TAB>绕过提交钩子
     ```
   - 动态/单单词的：改 `out\zh-cn.js` 里 `EXACT` 对象，加 `"Xxx": "中文",`
2. 重新生成（需要 Node.js，可选）：
   ```powershell
   node make.js         # 生成 out\renderer.js（可选，脚本本身也会实时替换）
   ```
3. 重跑 `一键汉化.ps1` 即可生效。

> 脚本是**实时读词典**做替换的，所以改了 tsv 直接重跑脚本就行，不依赖 make.js。

### 模板类文案（含 ${...} 的拼接句）

像右键菜单的 `Open in Android Studio`、`Ignore all .sys files (add to .gitignore)`、分支菜单的 `Update from main`，
在源码里是模板字符串，整串匹配改不到。这类写进 `dict-regex.tsv`（每行：`正则<TAB>替换文本`，`$1/$2` 引用捕获组）：

```
(Open in )($\{[^}]*\})        在 $2 中打开
(&Update from )($\{[^}]*\})   &从 $2 更新
(Create )($\{[^}]*\})         新建 $2
```

要点：用两个捕获组把「英文前缀」和「${...} 表达式」分开，只翻译前缀、原样保留表达式，
替换文本写成「在 $2 中打开」这种「中文 + 表达式 + 中文后缀」的形式。

> 正则词典会同时作用于 `renderer.js` 和 `main.js`。

## 六、常见问题

**Q：更新后变回英文了？**
A：官方更新会装到新的 `app-x.y.z` 目录，旧目录的汉化不影响新目录。重跑一次 `一键汉化.ps1` 即可（会自动为新版本单独备份）。

**Q：装完打不开 / 白屏？**
A：先 `-Restore` 还原验证。中文替换只动字符串字面量，理论上不会导致启动失败；若真出现，把 `backup\app-<版本>` 里的三个文件手工覆盖回去即可。

**Q：提交摘要框里的 `Update xxx.sys` 这类提示？**
A：已处理。它其实不是输入内容，而是 placeholder 里的「建议摘要」模板 `Update ${i}` / `Create ${i}` / `Delete ${i}`，已在 `dict-regex.tsv` 里改成「更新 xxx / 新建 xxx / 删除 xxx」。
注意：只改了 placeholder（显示层），实际提交写进 git 的仍是你自己输入的文字。

**Q：某些提示还是英文？**
A：属于第三层没覆盖到的动态拼接句。把整句英文发我，或按第五节加词条。

**Q：能卸载干净吗？**
A：`pwsh -File 一键汉化.ps1 -Restore` → 还原 3 个文件 + 删除 `zh-cn.js`，与全新安装一致。
